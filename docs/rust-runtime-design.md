# Rust Runtime MVP Design

This document records the current Rust Runtime MVP behavior. It describes only the verified implementation under [`rust/`](../rust/) and does not redefine or replace the existing Python implementation.

## Scope

The Rust MVP covers four crates in the Cargo workspace:

* [`rust/protocol`](../rust/protocol/) defines the event envelope, subject constants, and runtime payload structures.
* [`rust/bus`](../rust/bus/) provides an in-memory publish/subscribe bus for local runtime execution and tests.
* [`rust/runtime`](../rust/runtime/) provides runtime lifecycle state, task tracking, worker lookup, MVP LLM mediation, MVP tool mediation, handler registration, and bus-backed publish/handle behavior.
* [`rust/cli`](../rust/cli/) provides the local command surface, including the deterministic demo path.

The MVP keeps the Python runtime path compatible with the broader project. Rust is documented as an implemented workspace subset, not as a replacement for Python.

## Protocol Contract

[`EventEnvelope`](../rust/protocol/src/message.rs:5) is the Rust runtime event envelope. It includes canonical fields for `id`, `type`, `subject`, `source`, `timestamp`, `schema`, `payload`, `correlation_id`, `causation_id`, and `metadata`, plus current extension fields `scope` and `refs`.

[`EventEnvelopeFields`](../rust/protocol/src/message.rs:26) is the constructor input for [`EventEnvelope::new()`](../rust/protocol/src/message.rs:44). This keeps envelope construction explicit while preserving serde-compatible public fields.

Runtime payloads live in [`rust/protocol/src/payload.rs`](../rust/protocol/src/payload.rs). The MVP includes task assignment/result, agent lifecycle/error payloads, LLM request/response payloads, and tool request/result payloads.

Subject constants live in [`rust/protocol/src/subject.rs`](../rust/protocol/src/subject.rs). The MVP includes agent spawn/ready/exit/error subjects, task assign/result subjects, LLM request/response subjects, and tool request/result subjects. Dynamic task assignment subjects are generated by [`runtime_task_assign_for_agent()`](../rust/protocol/src/subject.rs:8).

## Bus Contract

[`BasicBus`](../rust/bus/src/lib.rs:84) is the in-memory MVP bus. It stores subscribers by subject, tracks whether the bus is closed, and records published envelopes for observation.

The [`MessageBus`](../rust/bus/src/lib.rs:59) contract supports subscribe, publish, unsubscribe, close, closed-state inspection, and handler-count inspection.

Current publish semantics are:

* [`publish()`](../rust/bus/src/lib.rs:146) returns a closed-bus error if the bus has been closed.
* Publishing to a subject with no subscribers succeeds.
* Every accepted envelope is appended to [`published_events()`](../rust/bus/src/lib.rs:101) before handler execution completes.
* Matching handlers are invoked asynchronously and handler task failures are mapped to the bus protocol error path.

These semantics support deterministic local testing without requiring NATS for the MVP path.

## Runtime Contract

[`ThalamusRuntime`](../rust/runtime/src/lib.rs:158) owns a bus, lifecycle state, registered event handlers, and spawned task handles.

The lifecycle state is represented by [`RuntimeState`](../rust/runtime/src/lib.rs:31). New runtimes start in the initialized state, [`start()`](../rust/runtime/src/lib.rs:252) transitions through starting to running, and [`stop()`](../rust/runtime/src/lib.rs:300) transitions running runtimes through stopping to stopped while closing the bus.

Task and worker support is intentionally minimal:

* [`TaskState`](../rust/runtime/src/lib.rs:65) stores a task id and optional assigned agent.
* [`WorkerRegistry`](../rust/runtime/src/lib.rs:100) registers worker ids with capability lists and supports lookup by id.
* [`spawn()`](../rust/runtime/src/lib.rs:202) returns a task handle and tracks active spawned futures until completion.

MVP mediation components are deterministic and local:

* [`MockLlmProvider`](../rust/runtime/src/lib.rs:120) returns a completed mock response using the request `prompt` or the last `messages` content, plus the requested model or the default mock model.
* [`EchoTool`](../rust/runtime/src/lib.rs:140) returns the request input as the tool output.

Default runtime subjects are registered by [`ensure_default_handlers()`](../rust/runtime/src/lib.rs:238) for agent spawn, task assign, LLM request, and tool request. When [`publish()`](../rust/runtime/src/lib.rs:391) receives a valid [`runtime.llm.request`](../rust/runtime/src/lib.rs:275), the default path serializes a deterministic [`MockLlmProvider`](../rust/runtime/src/lib.rs:120) response and publishes [`runtime.llm.response`](../rust/runtime/src/lib.rs:285) back through the bus. When it receives a valid [`runtime.tool.request`](../rust/runtime/src/lib.rs:294), it serializes an [`EchoTool`](../rust/runtime/src/lib.rs:140) result and publishes [`runtime.tool.result`](../rust/runtime/src/lib.rs:304) through the same bus-mediated path. Unknown runtime publish subjects are mapped to a runtime bus error by [`publish()`](../rust/runtime/src/lib.rs:397). Unknown handler dispatch subjects are mapped to a runtime schedule error by [`handle_event()`](../rust/runtime/src/lib.rs:418).

## CLI Contract

[`ThalamusCLI`](../rust/cli/src/lib.rs:7) defines the command-line surface. [`CLICommand`](../rust/cli/src/lib.rs:19) includes start, stop, status, list-agents, and [`RunDemo`](../rust/cli/src/lib.rs:35).

[`ThalamusCLI::run()`](../rust/cli/src/lib.rs:58) currently completes the local command paths without external services. [`RunDemo`](../rust/cli/src/lib.rs:88) is the MVP demo command path: it calls [`MockLlmProvider`](../rust/runtime/src/lib.rs:120) with the prompt `summarize runtime MVP`, calls [`EchoTool`](../rust/runtime/src/lib.rs:140) with `{ "text": "runtime MVP" }`, and prints the deterministic mock response plus echo result. The CLI manifest declares [`thalamus-protocol`](../rust/cli/Cargo.toml:8) and [`serde_json`](../rust/cli/Cargo.toml:11). The current CLI behavior is covered by the Rust workspace test artifact [`cargo-test-after-messages.log`](../artifacts/test-results/cargo-test-after-messages.log:1).

## Non-goals

The Rust MVP does not claim the following:

* Replacement of the existing Python implementation.
* Production NATS backend behavior for the Rust bus path.
* External MCP gateway mediation.
* Real LLM provider integration.
* Coverage percentage, security pass status, or performance benchmark results.
